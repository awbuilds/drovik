Constraints

The constraints are the product.

Drovik is deliberately smaller than a control panel and more honest than a dashboard. These rules decide what it will refuse to do.

Agentless

OpenSSH and SFTP only. No daemon, package, scheduled task or persistent helper on the managed host.

Least privilege

Drovik acts as your SSH user. It never silently escalates, and a permission failure is shown as a failure.

No false success

A mutation is only called successful after the remote host confirms it. State-changing panels re-read what they changed.

Terminal first

The graphical tools are helpers. A full interactive PTY remains one click away for the work no panel should hide.

Local ownership

Your database, your key, your backups. No account, no telemetry, no vendor cloud in the request path.

Capability-aware

Missing tools and distribution differences are reported with a stable error code, not hidden behind an empty panel.

Workspace

Dense enough to work. Quiet enough to think.

The panels mirror the way a Linux host actually works. Nothing is simulated for a screenshot; missing data is marked missing.

Nothing installed

SecretsStored SSH credentials use AES-256-GCM. The 32-byte key comes from the environment or a mounted file — never from SQLite, the repository or the image.

No telemetryThe service makes no analytics or crash-reporting request. The only remote connections are the ones you configure and operate.

Posture

Security is a release requirement.

Drovik is a gateway to systems that may hold sensitive data. The controls are deliberately boring, testable and enforced on the server side.

Credentials at rest

AES-256-GCM with a random nonce. The key lives outside the database and is decrypted only for a connection.

Strict host keys

Unknown keys require explicit fingerprint approval. A changed key blocks the connection; there is no insecure fallback.

Server-side authority

Every server-scoped request is authorized in the backend. Read-only roles and assignments are not a UI convention.

No secrets in logs

Structured logs redact credentials, cookies, keys and terminal or file contents. There is no default telemetry.

Install

One service. No agent on the other end.

Drovik is one small Go service with an embedded SQLite database and a separately mounted encryption key. Run it behind TLS, finish first-run setup, and keep backups of both the database and the key.

  • Docker Engine + Compose for the primary container path.
  • Linux amd64 or arm64 for the controller; managed hosts stay yours.
  • A TLS reverse proxy in front of 127.0.0.1:8080.
  • One encryption key, generated once and backed up separately.

Full install and upgrade guide

deploy/compose 
git clone https://github.com/awbuilds/drovik.git
cd drovik/deploy/compose
cp .env.example .env
# set DROVIK_PUBLIC_URL and DROVIK_TRUSTED_ORIGINS
mkdir -p secrets
openssl rand -base64 32 > secrets/encryption.key
chmod 600 secrets/encryption.key
docker compose up -d --build

Pin the release tag in production. Keep the key out of the database volume.

FAQ

The short answers.

No account, no agent, no telemetry — and no pretending that a Linux host is simpler than it is.

Does Drovik install an agent?

No. It uses the OpenSSH server and SFTP subsystem already on the host. There is no daemon, package or persistent helper.

Does it need root?

No. Drovik acts as the SSH user you configure. It never escalates silently, and remote permissions remain authoritative.

Is there telemetry?

No analytics, no crash reporting and no vendor cloud. Your instance stores what it needs locally; nothing is sent to the project.

Can several people use it?

Yes. Local users, administrator/operator/read-only roles, per-server assignments, TOTP MFA and optional OIDC sign-in with explicit account linking.
