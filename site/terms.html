5. Operator responsibilities

If you deploy Drovik, you are responsible for the instance and its data. At a minimum:

  • Network and TLS. Put the service behind a TLS reverse proxy, bind it to loopback or a private interface, and restrict who can reach the login and setup pages.
  • First-run setup. Complete setup before the instance is reachable by untrusted users. Until the first administrator exists, the setup route is claimable.
  • Identity and access. Use a strong administrator password, review local users, roles and per-server assignments, and remove access that is no longer needed.
  • Secrets. Generate the encryption key once, keep it out of the database and repository, restrict its file permissions, and store it separately from backups.
  • Backups and upgrades. Back up the database and the key, test restoration, read the release notes and treat a failed migration as a failed upgrade.
  • Compliance. Establish your own lawful basis, notices, retention and access policy for the data you hold. Comply with the law that applies to you and to the managed hosts.
  • Host authority. Drovik acts as the configured SSH user. You are responsible for what that account can do and for the commands you run through the terminal or snippets.

6. High-risk features

Some features are deliberately powerful. They are not a substitute for your own judgment or for the remote permission model.

  • Docker. Docker access can be equivalent to root on the host. Drovik reaches it through the host's CLI over SSH and exposes enumerated actions only, but an operator with Docker access can still affect containers and host resources. Restrict the assignment and review actions.
  • Terminal and snippets. These execute commands as your SSH user. Snippets preview and confirm a substituted command, but the operator remains responsible for the command's effect. Never store secrets in a snippet.
  • Process and service actions. Signals and service changes affect running systems. A confirmation dialog is not a guarantee of safety; the remote permissions and your review are.
  • File operations. Delete and overwrite operations change remote files. Drovik validates paths and guards recursion, but it cannot know which files are important to you.
  • Destructive host operations. They are disabled by default and, when enabled, administrator-only and confirmed. They can destroy data or cut off a host. Do not assume the UI covers every administrative task or that a confirmation dialog makes an operation safe.
