v1.2.0

8 November 2026

securitycurrent

A security patch for the Phase 9 line, after a second source-first audit of the v1.1.0 tree. Seven confirmed findings were fixed:

  • Snippet substitution bounds: one request could expand into gigabytes before the 64 KiB check. Per-value limits, a running-budget builder and declaration validation bound the work.
  • Last-administrator race: two administrators deactivating each other concurrently could leave zero active administrators. A statement-level post-state guard and conflict mapping close it.
  • Collector cost: section assembly was quadratic in the remote line count. The builders are linear with a per-section line cap.
  • Truthful outcomes: a failed post-signal state read was reported as “not running” with a success audit. It now returns OUTCOME_UNKNOWN with an unknown audit outcome.
  • Audit durability: a delivered signal could lose its audit row when the request was canceled. Audit writes use a detached, bounded context.
  • Metric finiteness: non-finite load or uptime could be persisted and turn APIs into empty 200 responses. Finiteness checks, storage guards and marshal-before-write JSON reject it.
  • Metric duplicates: concurrent overview requests persisted duplicate samples. A unique (server_id, collected_at) index uses ON CONFLICT DO NOTHING.

Also: alert-rule cardinality and identifier length are bounded, Docker inspect labels are sanitized, advanced responses carry no-store, and container base images are pinned by digest. The dependency review upgraded golang.org/x/crypto past GO-2026-5932 and reduced workflow token permissions.

v1.1.0

8 November 2026

featuresstable

The first release with advanced management. The core workspace is unchanged; the new surfaces are deliberately read-first where a mistake would change the host.

  • Docker: inspect containers and images, view logs and inspect data, and start, stop, restart or remove a container by a validated ID. Access is through the host's Docker CLI over SSH; no Docker socket is mounted into Drovik.
  • Host diagnostics: read-only storage, network, package and scheduled-task views. No destructive disk, firewall, interface, package or cron mutations.
  • Snippets: named command templates with variables, shell-quoted substitution, a preview, target confirmation and audit. Snippets execute as the SSH user.
  • Local users and assignments: administrator, operator and read-only roles, per-server read/write assignments, password reset with session revocation and a last-administrator invariant.
  • History and alerts: bounded local metric retention, charts and in-app threshold rules. No external notification channels.
  • Hardening: read-only assignments block the terminal and every mutation path; Docker is labelled as potentially root-equivalent; advanced-management boundaries are recorded in ADR 0013.

v1.0.1

8 November 2026

securitypatch

A security patch for the first stable line, after a source-first audit of the v1.0.0 tree. Five confirmed findings were fixed:

  • High — credential exposure: changing auth_method without a new credential could reinterpret a stored private key as a password. Method changes now require a credential of the new type, and secrets are never decrypted under a different method.
  • Medium — terminal lifetime: PTYs survived logout, revocation and session expiry. Terminals are now bound to the application session, closed on logout and revalidated every 30 seconds.
  • Medium — egress bypass: IPv6 zone identifiers bypassed the deny policy. Zone identifiers are rejected and the deny checks are explicit.
  • Medium — upload mode: uploading over a 0600 file could widen it. Staging is private, the final mode is applied before the atomic rename, and a failed chmod aborts.
  • Medium — journal bounds: the parser ignored the requested line count. Parsing stops at the requested count and marks the window truncated.

v1.0.0

8 November 2026

stableMVP

The first stable MVP for self-hosted, agentless Linux server management.

  • First-run setup, Argon2id authentication, server-side sessions and CSRF.
  • Encrypted SSH credentials and strict host-key approval, with changed-key blocking.
  • An authenticated WebSocket PTY terminal with resize and bounded session counts.
  • SFTP browsing, streamed transfers, bounded editing and path/symlink protection.
  • Agentless CPU, load, memory, filesystem, network and uptime overview.
  • Process discovery with SIGTERM/SIGKILL identity checks; systemd discovery and enumerated actions with state re-reads; bounded journal logs.
  • Scoped audit history, accessibility skip navigation and the stable error-code catalog.
  • Tag-driven release pipeline, checksums, a distroless container image and deployment guidance.

betaprerelease

The public beta of the single-operator MVP. It established the workspace, authentication, host-key trust, terminal, files, monitoring, processes, services and logs. The beta notes remain the record of what that line did not do.

v0.1.0-beta.1 release · Beta notes

Upgrading? Back up the SQLite database and the encryption key before every version change. Migrations are forward-only. A failed migration is a failed upgrade; restore the backup rather than serving a half-migrated database.
