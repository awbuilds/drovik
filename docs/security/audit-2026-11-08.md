# Security audit — 2026-11-08

A source-first security audit of the `v1.0.0` tree was completed before this patch release. The
full report and evidence live outside the repository; this page records the confirmed issues and
their fixes without publishing a live exploitation guide.

## Confirmed and fixed

| Severity | Issue | Fix |
|---|---|---|
| High | Changing `auth_method` from private key to password without a new credential reinterpreted the stored private-key PEM as a password and could send it to an attacker-selected SSH host | Method changes now require a credential of the new type; stored secrets are never decrypted under a different method. Regression test added. |
| Medium | Established terminal PTYs survived logout, revocation and session expiry | Terminals are bound to the application session ID, closed on logout, and revalidated every 30 seconds. Regression test added. |
| Medium | IPv6 zone identifiers (`::1%lo`, `fe80::1%lo`) bypassed the egress deny policy | Zone identifiers are rejected and loopback/link-local/multicast/unspecified checks are explicit. Regression test added. |
| Medium | Uploading over a `0600` file widened it to the SFTP server default (`0644`) | Staging files are created private, content is written, the final mode is applied before rename, and a chmod failure aborts. Regression test added. |
| Medium | The journal parser ignored the requested line count, allowing hundreds of thousands of entries from a malicious host | Parsing stops at the requested count and marks the window truncated. Regression test added. |

## Second run — Phase 9 tree

A second source-first run covered the Phase 9 tree (`5771341`, `v1.1.0`). Confirmed, independently
verified and fixed in `v1.1.1`:

| Severity | Issue | Fix |
|---|---|---|
| Medium | Snippet substitution expanded one request into gigabytes before the 64 KiB check | Bounded per-value limits, running-budget builder and declaration validation |
| Medium | Two administrators deactivating each other concurrently could leave zero active administrators | Statement-level post-state guard plus `ErrLastAdmin` mapping |
| Low | Collector section assembly was quadratic in remote line count | Linear builders with a per-section line cap |
| Low | A failed post-signal state read was reported as "not running" with a success audit | Explicit `outcome_unknown` and unknown audit outcome |
| Low | A delivered signal could lose its audit row when the request was canceled | Detached bounded audit context |
| Low | Non-finite host load/uptime could be persisted and turn APIs into empty 200 responses | Finiteness checks, storage guards and marshal-before-write JSON |
| Low | Concurrent overview requests persisted duplicate metric samples | Unique `(server_id, collected_at)` index with `ON CONFLICT DO NOTHING` |

The same run also fixed unbounded alert-rule cardinality, sanitized Docker inspect labels, added
`no-store` to advanced responses and pinned container base images by digest.

## Validation leads

Twelve additional source-grounded leads were recorded with exact traces and non-destructive
validation plans. They are not confirmed vulnerabilities and were not assigned severity. They cover
forwarded-header rate-limit identity, Argon2id concurrency, terminal/SFTP operation deadlines,
recursive-delete symlink races, SFTP session accounting, process outcome reporting, audit-write
cancellation, omitted metadata ranges, directory materialization, local file permissions and logout
failure reporting. Several are documented beta limitations; the rest are candidates for follow-up
hardening.

## Audit boundary

The audit combined source review with bounded local Go tests in disposable source copies inside
Docker (`--network none`, read-only root/source, tmpfs-only writes, memory/PID limits). No deployed
endpoint, real credential or shared host was used. Real-host compatibility, PolicyKit/journal
variants, cloud metadata reachability and browser screen-reader behavior remain owner-observed work.

## Third run — final Phase 9 tree

A third source-first run covered the expanded Phase 9 tree at `95e0d06` and was independently
verified on the remediation tree `0ab6271` before `v1.3.0`. Six findings were confirmed; all were
fixed and re-verified.

| Severity | Issue | Fix |
|---|---|---|
| High | OIDC linking required only a session and created a persistent passwordless login for the account | Link start requires the local password and, when MFA is enabled, a current authenticator/recovery code; state is bound to an HttpOnly cookie and the initiating session |
| Medium | MFA setup could disable and replace an active factor from a session alone | Enrollment requires the password; replacement also requires a current authenticator/recovery code |
| Medium | OIDC login state was not bound to the browser, enabling login CSRF/session swapping | Short-lived HttpOnly SameSite state cookie is compared at the callback |
| Medium | A webhook bearer URL could reach application logs on delivery failure | Delivery errors are URL-free; only the rule ID is logged |
| Low | The alert cooldown claim was non-atomic and could double-deliver webhooks | Conditional database claim returning rows affected |
| Low | Canceled or timed-out destructive host operations were audited as definite failures | `OUTCOME_UNKNOWN` with a non-success audit outcome |

Fourteen additional leads remain in the run record with traces, blockers and non-destructive
validation plans. They cover forwarded-header rate-limit identity, Argon2id concurrency, denied-login
audit growth, live-terminal assignment revocation, SSH/SFTP deadlines and accounting, recursive-delete
symlink races, local database/key modes, Vault full-row update rollback, firewalld deny semantics and
silent `crontab -l` handling. None is assigned severity without the missing deployment or runtime
fact.

The run used source review and bounded local tests only. No live identity provider, Vault server,
TOTP device or real managed host was exercised.

## Post-audit hardening — v1.3.1

Live end-to-end testing against a disposable Lima Ubuntu VM found three host-compatibility
defects that the audit's source review could not see:

- Removing a **running** Docker container failed because plain `docker rm` refuses it. The
  confirmed remove action now uses `docker rm -f` and has a command regression test.
- Editing or uploading over an existing file failed on OpenSSH because it refuses the standard
  SFTP rename with an existing destination. Drovik now uses the `posix-rename` extension and
  fails closed when the server does not expose it.
- Creating a managed task failed for an account with no crontab because `crontab -l` reports
  `no crontab for <user>` on stderr. Only that explicit diagnostic is treated as empty; silent
  and truncated reads fail closed.

The same run also exercised a real Keycloak OIDC link/login flow, Docker list/logs/inspect/
stop/start/restart/remove, the terminal WebSocket, packages, cron, services, files, and
feature-flagged storage/network operations. FreeBSD under Lima still needs QEMU, which was not
installed on the test machine; OpenBSD/NetBSD have no Lima template.
