# 2026-11-08 Phase 9 OIDC single sign-on

## Task / Area
Add optional OpenID Connect sign-in with explicit account linking.

## Current State
- Config: `DROVIK_OIDC_ENABLED`, `DROVIK_OIDC_ISSUER`, `DROVIK_OIDC_CLIENT_ID`,
  `DROVIK_OIDC_CLIENT_SECRET` (optional for PKCE public clients), `DROVIK_OIDC_REDIRECT_URL`.
  Startup validates absolute http(s) URLs and fetches discovery before serving.
- `internal/oidc`: authorization-code + PKCE (S256), issuer equality check, no redirect following,
  10 s timeout, 1 MiB response bounds, single-use five-minute in-memory state capped at 1,000, and
  a 30/min per-client start limit.
- Account model: `users.oidc_issuer`/`oidc_subject` with a unique partial index. **No
  auto-provisioning and no username matching at login.** A signed-in user links from Settings
  (`POST /auth/oidc/link`) and only stored `(issuer, subject)` pairs can sign in.
- Endpoints: `GET /auth/oidc/status`, `GET /auth/oidc/start`, `GET /auth/oidc/callback`,
  `GET|POST /auth/oidc/link`, `POST /auth/oidc/unlink` (password confirmed).
- UI: SSO button on the login page when enabled, error explanations for denied/expired flows, and a
  Settings card to link or unlink the identity.

## Decisions
- Link, never auto-bind: prevents an IdP user from taking over a local account by choosing a
  matching username.
- The IdP policy is the SSO authentication boundary; local TOTP is not also required for SSO
  sign-in (documented in ADR 0013 and `.env.example`).
- State is in-process, which matches the single-instance SQLite deployment model.
- Unlinking requires the local password; SSO never removes the password fallback.

## Build / Test Status
- `go test ./internal/oidc` passes (discovery, PKCE, single-use state, link-mode guard).
- `go test -race ./internal/httpapi -run TestOIDCLoginFlow` passes (link, SSO login, replay denial,
  unlinked-account denial, no auto-provisioning, unlink).
- Frontend tests cover the SSO entry point and the `no_account` explanation.
- `make verify` is run before merge.
