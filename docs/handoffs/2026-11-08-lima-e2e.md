# 2026-11-08 Lima live SSH end-to-end test

## Task / Area
Run Drovik against a disposable Lima Ubuntu VM as a live SSH host.

## Environment
- Lima 2.3.0, `vz` backend, Ubuntu 26.10, 2 CPUs, 2 GiB RAM, 10 GiB sparse disk.
- Created with `--mount-none`; no host filesystem was mounted into the guest.
- A dedicated root SSH key and root `prohibit-password` login were used only inside the VM.
- Drovik ran locally against a temporary SQLite DB and loopback HTTP port.
- A localhost-only SSH tunnel was used for a stable endpoint; it was removed afterward.

## Covered end to end
- Host-key unknown/approve flow, SSH key auth and capability detection.
- Overview, files list/mkdir/touch/write/read/delete, process list/signal, systemd restart,
  journal read, package install/list/remove, managed cron task create/list/delete.
- Destructive storage format/mount/umount and GPT partitioning on a separate 256 MiB virtual disk.
- Destructive network dummy link, address, route and ufw allow.
- Terminal WebSocket: connected, ran `echo TERMINAL_E2E`, received the output.
- Teams read/write access, audit CSV export, snippet run/export/import.

## Bugs found by the live test and fixed
1. **SFTP overwrite failed on OpenSSH.** Editor save/upload used the standard SFTP `Rename`, which
   refuses to replace an existing target; OpenSSH returned `SSH_FX_FAILURE`. Both paths now use the
   `posix-rename` extension and fail closed if it is unavailable.
2. **Managed task creation failed for an empty crontab.** `crontab -l` exits non-zero with
   `no crontab for <user>` on stderr; the old code treated any stderr as an error and returned 502.
   The code now treats only that explicit diagnostic as empty, fails closed on silent errors, and
   rejects truncated crontab output before a read-modify-write.

## Cleanup
The Lima instance, extra disk, download cache, tunnel and temporary Drovik database were deleted.
Colima and its containers were left untouched. No host mount was exposed to the VM.

## Not covered
Live OIDC provider, Vault server, Docker actions, FreeBSD/OpenBSD hosts, and a real cloud network.
