# 2026-11-08 Phase 9 local MFA

## Task / Area
Add local TOTP multi-factor authentication with encrypted secrets, recovery codes and a login
challenge.

## Current State
- Migration `00005_mfa.sql`: `users.mfa_secret` (AES-GCM, AAD `user:<id>:mfa`), `users.mfa_enabled`
  and `mfa_recovery_codes` with hashed single-use codes.
- `internal/auth/totp.go`: 160-bit secrets, RFC 6238 SHA-1/6-digit/30s validation with ±1 step,
  otpauth URIs and recovery code generation/hashing.
- Endpoints: `GET /auth/mfa`, `POST /auth/mfa/setup`, `POST /auth/mfa/enable`,
  `POST /auth/mfa/disable` (CSRF on mutations).
- Login accepts `totp`; enabled accounts receive `AUTH_MFA_REQUIRED` or `AUTH_MFA_INVALID`; recovery
  codes are consumed once.
- UI: login shows the authenticator field on challenge; Settings has an MFA card with enrollment,
  recovery-code display and password-confirmed disable.
- Logout no longer claims revocation on failure and clears the React Query cache on success and
  login.

## Decisions
- TOTP secrets are encrypted with the same key as SSH credentials but a distinct AAD.
- Recovery codes are stored as SHA-256 hashes, shown once and consumed atomically.
- There is no email recovery; losing the authenticator and recovery codes locks the account, as the
  UI states.
- OIDC/SSO remains a separate identity decision.

## Build / Test Status
- `go test -race ./internal/httpapi -run TestMFAEnrollmentAndLogin` passes (enrollment, challenge,
  wrong code, success, recovery code single use, disable).
- `make verify` is run before merge.
